# Совместимость с Express 5

Проверено для Express 5.2.1 и qs 6.16.0 из Dependabot PR #16.
Multer остаётся на версии из этой ветки; его обновление не входит в миграцию.
Dockerfile и CI используют Node.js 24.

Основание: [официальное руководство миграции](https://expressjs.com/en/guide/migrating-5/).

## Изменения сервера

- `/media/*mediaPath` и `/preview/*mediaPath` используют именованные wildcard-параметры.
  Массив декодированных сегментов соединяется через `/`, без повторного `decodeURIComponent`.
- До нормализации пути отклоняются пустые сегменты, `.` и `..`, NUL, а также `/` и `\`
  внутри сегмента, в том числе полученные из `%2F` и `%5C`. Такие запросы возвращают 400.
  Каждый сегмент корректного имени нужно кодировать отдельно. Буквальное имя `%2e%2e`
  передаётся как `%252e%252e` и остаётся буквальным именем, а не переходом к родителю.
- Сохраняются `requireAuth`, проверка расширений, типа файла и `realpath` относительно
  `MEDIA_ROOT`. Симлинки на файлы и каталоги вне корня получают 403, отсутствующие и
  неподдерживаемые файлы — 404. Эти ответы не попадают в SPA fallback.
- SPA использует `/{*splat}`, включая `/`. `sendFile` получает `root: distDir`, чтобы
  размещение приложения внутри скрытого каталога не блокировало выдачу `index.html`.
- Обработчик ошибок учитывает как `statusCode`, так и `status`, включая ошибки
  декодирования URI от нового router. В ответ допускаются только целые коды 400–599.
- Callback `app.listen` проверяет ошибку: занятый порт завершает процесс с ненулевым
  кодом без сообщения об успешном запуске. Для `PORT=0` выводится фактический порт.
- Загрузка использует `req.body?.paths`: в Express 5 непрочитанное тело равно `undefined`.

## Остальные проверенные изменения

- `req.query` только читается; приложение использует простые параметры `path` и `size`,
  без зависимости от вложенных объектов extended parser. Новый simple parser подходит.
- Остальные обращения к `req.body` уже используют optional chaining; Multer заполняет
  тело multipart-запросов. CSRF, JSON и multipart проверяются HTTP-тестами.
- Существующий `asyncHandler` перехватывает rejected promises и вызывает `next`;
  он совместим с Express 5 и сохранён без рефакторинга.
- Нет удалённых API и старых сигнатур `send/json/redirect`, `req.param`, `app.del`,
  `app.param(fn)`, `express.static.mime` и старых опций `sendFile/static`.
- Не используются `req.host`, `app.router`, `urlencoded`, view engines, `res.vary`
  и устаревшие варианты `accepts*`. `clearCookie` передаёт только `path`.
- Статические файлы остаются с безопасной политикой dotfiles по умолчанию;
  выдача JavaScript с MIME `text/javascript` проверяется тестом.

## Проверки

```bash
npm ci
npm run lint
npm run build
npm run test:regression
```

Регрессионный набор запускает отдельный процесс реального сервера, создаёт временную
медиатеку и кеш, проверяет оригиналы и генерацию WebP-превью, вложенные имена с
кириллицей, пробелами, запятыми и `%`, Range/HEAD, SPA и статические ресурсы,
ошибочные пути, симлинки, авторизацию, CSRF, JSON и multipart. Он также запускает
существующий `scripts/smoke-test.mjs` и проверяет ошибку занятого порта.
Тестовые данные удаляются после завершения. Видео проверяется на уровне выдачи
байтов и Range; извлечение кадров через ffmpeg этот набор не тестирует.

CI запускает регрессионный набор после сборки, затем существующие smoke-проверки
обычного приложения и Docker-образа.
